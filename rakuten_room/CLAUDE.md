# rakuten_room（楽天アフィリエイトの自動運用）

楽天ROOMの投稿・いいね・フォローなどを、サーバーで毎日自動で回すツール。**売上はすべて楽天ROOM経由。** Threads と Instagram は 2026-10-20 に投稿を止めた。買い時ナビ（kaidokinavi.com）は自動更新だけ。
ユーザーへの返事・報告は日本語。ユーザーを名前で呼ばない。

## 進め方の決まり（厳守）

- **点検エージェントは入口と出口で必ず使う。**
  - 入口：作る前に、設計（何をどう変えるか）を点検させる。
  - 出口：本番に入れる前に、できた変更（コミット）を点検させる。
  - エージェントには「読み取りのみ・否定の目線」で頼み、点検の観点に「LESSONS.md の過去の失敗の繰り返し」と「下の運用ルール違反」を必ず入れる。
  - 途中の細かい作業ごとには呼ばない（クレジット節約）。
- 反映したら、サーバーの実際の記録で効いたことを確かめてから「直った」と言う。
- 報告は「確認済み」と「見込み・推測」を分ける。確かめていないことは断定しない。
- 詳しい経緯は LESSONS.md、構成は ARCHITECTURE.md。全部を毎回読み直さず、必要な部分だけ開く。新しい不具合は LESSONS.md の表に追記する。

## 運用ルール（破らない）

- **件数は減らさない**（ユーザー指示）。速さ・揺らぎの調整は、時間をかける方向で行う。

- **削除：** 2025-01-01 より前の投稿だけ（販売終了 → 古い順、1日600件をゆっくり）。このツールの投稿（2025年以降）は、販売終了でも絶対に消さない。
- **コードを反映する再起動：** 3:00 に予約する（ジョブが動いていない時刻）。
  `sudo systemd-run --on-calendar='YYYY-MM-DD 03:00:00' --unit=rr-restart-MMDD /bin/systemctl restart rakuten_room_webapp`
- **反映の前：** サーバーのファイルが git の HEAD と同じかを確かめる（`tr -d '\r'` してから diff）。サーバーは git ではなく、scp でファイルを配っている。
- .env・a8_links.yaml・vc_links.yaml・google_sa.json はコミットしない。秘密情報は表示しない。
- Claude API（Haiku）は ROOM の紹介文づくりだけに使う（1日 約60円）。

## 1日の流れ（主なもの）

| 時刻 | ジョブ | 中身 |
|---|---|---|
| 6時台 | prepare | 候補選び（約360件）→ 紹介文をつくる |
| 8〜22時 | room_post（8回） | 1日150件。5と0の日は×1.3、セール中は×1.5。残り件数を残りの回数で割って投稿する |
| 9〜22:45 | いいね12回・フォロー13回・フォロー解除4回 | いいね700件、フォロー500件（新規のみ）。1回は残り÷残り回数に±10%、1時間上限の半分まで |
| 0:30〜2:00・3:30〜5:00・14〜17時（6回） | room_prune | 削除600件。1回120件まで・1時間150件まで（超えたら待つ）・1件8〜18秒。2:45〜3:15は削除しない |
| 23時台 | room_collect | コレクションの振り分けと入れ替え、投稿の残り確認、成果の記録 |
| 23:56ごろ | report | 「予定と実績」の通知 |

## 主なファイル

- `src/selector.py`：候補の出どころ（ランキング・キーワード・季節・売れた店・ROOM内検索）と加点
- `src/poster.py`：投稿
- `src/engage.py`：いいね・フォロー・フォロー解除
- `src/pruner.py`：削除
- `src/room_collections.py`：コレクション・成果の記録・売上の突き合わせ
- `src/sale_calendar.py`：セールの検知
- `src/webapp.py`：スケジューラ
- `src/daily_report.py`：毎晩の通知
- `config.yaml`：各種の件数・時間帯・上限
