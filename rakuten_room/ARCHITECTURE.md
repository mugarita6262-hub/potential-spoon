このファイルは「どこを変えると何に効くか」を見失わないための地図。**変更の前に LESSONS.md（経緯と教訓・進め方の決まり）を読むこと。**仕組みを足したり変えたりしたら、ここも直す。

## 3. ROOM 投稿の作り方（売上が出ている唯一の経路）

```
gather_candidates（selector.py）
  ├ ranking    楽天ランキング 15ジャンル×30件
  ├ keywords   SALE / 訳あり / クーポン / まとめ買い（検索結果のページはランダム）
  ├ room_search ROOM 内で反応が出ている商品（16語のうち6語ずつ）
  ├ seasonal   その月に買われるもの（2026-10-18 追加・まだ再起動していない）
  ├ sold_shops 売れた店の人気商品（同上）
  └ favorites  楽天のお気に入り（※サーバーではブラウザが起動できず、毎回スキップ）
→ claims_filter（薬機法リスクの商品を外す）→ 重複を除く → 投稿済みを除く（定番は21日たてば再投稿可）
→ score_items（scoring.py）
     レビュー件数 .35 ／ 評価 .20 ／ ランキング順位 .25 ／ 価格帯 .10 ／ ポイント倍率 .10
   ＋加点：定番 +0.15、商品名にセール表記 +0.12、
     ポイント5倍 +0.06・10倍 +0.12（未反映）、売れた店 +0.05（未反映）
→ 上位240件を下書きにし、紹介文を作る
→ 1日の目標 = post_count（100。10/27まで +50 で150）× セール倍率
     （5と0の日 ×1.3、セール開催中 ×1.8。sale_calendar.py）
```

**加点が重なりすぎている。** ポイントは「スコアの重み」「商品名のセール表記（ポイント○倍）」「ポイント加点」の3か所で数えている。どれがどれだけ効いたか分からない状態。

## 4. Threads / Instagram / 買い時ナビ

- **Threads**（main.py の cmd_sitedrop / cmd_trivia / cmd_calendar）
  - 「値下がり情報アカウント」の縮小版。
  - 判定は 2026-11-30。Threads 経由の楽天リンククリックが累計30回未満なら、値下がり速報を止める。
  - 止めているもの（runs=0）：sns、a8、digest、sitepost、trend。
- **Instagram**：1日1件。プロフィールのリンク先は買い時ナビ。サイト側に「Instagramで紹介中」の帯がある。
- **買い時ナビ**（site_builder.py、約2,900行）
  - 58ジャンル、約1万2千商品の価格を記録している。
  - 値下がりの定義は price_history.price_drop。2026-10-18 に「30日の中央値比」に変えたが、ユーザー方針で見直す予定（6章）。

## 5. 記録と測定（data/）

| ファイル | 中身 | 書き込み |
|---|---|---|
| posted.json | ROOM 投稿の記録（商品・日時のみ。**選んだ理由・出どころは残していない**） | room_post |
| drafts/日付_*.json | その日の候補・紹介文・目標数 | prepare |
| affiliate_report.json | 楽天アフィリの月の合計と注文明細（経由元つき） | room_collect |
| room_metrics.json | ROOM の直近7日の投稿・いいね、月の売上 | room_collect |
| google_stats.json | GA4（流入元・入口ページ・楽天クリックとその流入元）、Search Console | room_collect |
| price_history.json | 1商品1日1件の価格 | collect / site |
| sns_posted.json | Threads・Instagram の投稿 | 各投稿ジョブ |
| engage_log / follow_log | いいね・フォロー | engage |
| pruned.json | 削除した投稿 | prune |

**欠けているもの：売上と仕組みのつながり。** 注文明細と posted.json は商品名で突き合わせられる（10/16 の売上2件は、どちらも投稿から1〜2時間後）。ただ、その商品が「どの出どころ・どの加点で選ばれたか」が残っていないので、仕組みの良し悪しを測れない。

## 6. 分かっている問題（2026-10-18）

1. **期限切れのセール表記にも加点している。** 例：「17日09:59まで」の商品を 10/17 18:40 に投稿した。10/18 の候補1位も期限切れの P10倍。候補選びが朝の1回だけなので、昼のセール情報も古くなる。
2. **ポイントを3か所で数えている**（3章）。
3. **使われていない経路が残っている。**
   - favorites はサーバーで毎回失敗している。
   - optimizer（config.yaml を自動で書き換える）と server_sync（gcloud 時代のもの）は、サーバーでは動いていない。
4. **買い時ナビの「お得」が少なすぎる。** 中央値基準で値下がりは23件になった。サイトの意味が薄れるので、次の方向で見直す。
   - 値下がりは「記録中の最高値より○%安い」と正しく書いて戻す。
   - ポイント込みの実質価格（5倍以上は約630件）を足す。
   - クーポン・セールは期限つきで扱う。
5. **変更が測定とひもづいていない。** 足した仕組みの効果を、あとから切り分けられない。
